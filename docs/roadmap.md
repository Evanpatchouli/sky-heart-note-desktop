# 俱乐部平台路线图

交付顺序为 **P1 送心 → P2 代跑 → P3 陪玩**。以首个能真正结算的送心订单验证共用能力，再接入其他业务线。阶段按可验收的结果划分，排期和负责人可随实际开发补充。[业务范围](club-business.md) · [送心规则与算例](heart-delivery.md) · [可勾选的任务清单](todo.md)

## P1 · 送心

团员端与客户端使用[设计规范和可点击原型](design/README.md)走查下单、主动派发、通知抢单及跨期补退。初稿供评审，开发与发布按下列里程碑单独验收。

| 里程碑 | 交付给谁、能做什么 | 通过条件 | 相关任务 |
| --- | --- | --- | --- |
| 1. 全团能协作 | 管理层维护成员、职责和团抽。派单人与接单人引用同一笔订单 | 两名团员能在各自权限范围内协作。旧个人库有可复核的归属和迁移方案。老板仅能查看自己的订单 | P1-01～P1-05 |
| 2. 跑通两种来源的普通单 | 两种来源均由派单人主动发布，发布后通知全团。团员点击通知进入接单区，再接单、解锁、逐日报数 | 客户端下单覆盖老板指定、系统随机指定两种选人方式。验收全团站内可查、并发抢最后一个份额仅一人成功，100 颗、10 天、两人各 5 个号的普通单核平 51.00 元，日报与结算可安全重试 | P1-06～P1-11、P1-16～P1-18、P1-24～P1-26 |
| 3. 活动单和异常单能结清 | 财务和派单人可对照原付款、实际履约与变更，处理买赠、折扣、跨期、退款、减免及扣款 | 双倍期 1 次到账 2 颗，剩余减 2，派抽和团抽按该单同一口径复算。跨期验收补款续送、拒补停送退款两个结果。买赠验收团员正常得酬、团费单列活动支出 | P1-12～P1-18、P1-23 |
| 4. 三端可在实际设备工作 | 管理、团员、客户三个 PWA 均可安装。手机团员端、客户端以底部 Tab 进入主要业务 | 在安装态走通老板下单、派单发布、锁屏通知点入接单区、抢单与填报、客户查单及管理核对。未授权推送的团员也能从站内接单。手机、Pad 横竖屏可点按，桌面支持鼠标键盘 | P1-19～P1-22、P1-27～P1-28 |

终端适配可从里程碑 1 并行开始。涉及定价或资金归属的规则，应先用业务方认可的订单写清输入和应得金额，再启用该类订单的自动结算。未决项、影响环节和负责人需要回答的问题集中在[送心业务细则](heart-delivery.md)。

## P2 · 代跑

**进入条件**是共用订单、成员、收退款和结算流程已在 P1 得到验证，且业务方可提供一笔普通代跑单和一笔异常单。先明确老板购买的服务内容、接单交接、计价单位、完成凭据和退款方式，再决定要增加的字段与页面。

**完成条件**是用业务方认可的代跑样单，从报价、派接单和履约走到客户验收、收退款核对与结算。团员和客户可在手机底部 Tab 找到相应订单，管理端能按业务线核对金额。对应 P2-01～P2-03。

## P3 · 陪玩

在代跑阶段之后开展陪玩交付。先取得真实陪玩业务样单，确认如何约定服务、是否需要预约时段、如何确认开始与结束、怎样计费，以及取消或争议如何处置。

**完成条件**是普通单和异常单均按确认后的陪玩口径验收。客户、执行团员和财务能对上同一笔服务及其结算记录。对应 P3-01～P3-03。P2、P3 各自的计价、凭据和分成细则由业务调研产出。
