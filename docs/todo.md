## P1 · 俱乐部共用基础

- [x] **P1-29 用户采用四位短 ID**。直接将原始用户表的主键 `users._id` 定义为字符串。服务端从数字 `0–9` 与大写字母 `A–Z` 生成恰好 4 位的编号，保留前导零，共 `36⁴ = 1,679,616` 种组合。以主键唯一约束兜底，遇到编号冲突时重新生成。同步调整登录会话、登录日志、系统账号初始化、按用户定位团员工作区等引用，成员列表和选择器以“昵称 + 短 ID”区分同昵称用户。项目尚未上线，以空库初始化验收，不新增 migrator 迁移，不转换历史数据。验收包括四位格式、冲突重试、同昵称不同 ID 和按短 ID 查询。

- [ ] **P1-01 确认职责与订单权限表**。列出老板、派单人、接单人、团长、副团长和财务能读写的内容，记录同单自接与异常审核决定。验收用同一团员在两笔订单互换派/接身份走查。关联 Q4～Q6。
- [x] **P1-02 建立俱乐部共享订单与成员关系**。订单来源固定为“直接派单”或“客户端下单”。分别记录创建人、客户及游戏账号、本单派单人、实际派发状态、接单份额和执行账号，以及业务类型。俱乐部成员可带“派单”身份标记。验收不同团员按授权协作，老板可查看自己的多笔订单，两种来源可分别查询。依赖 P1-01。
- [x] **P1-03 制定旧个人库迁移与核对方案**。以原所有者及本地记录 ID 标识来源。处理跨库同号、文本派单人、无法匹配老板或成员的记录。验收用两份同 ID 的旧库演练，列出需人工认领的项，重复导入不重单，旧“实际结算”字段不会直接增加余额。依赖 P1-02。
- [x] **P1-04 落实业务对象级授权**。服务端校验俱乐部成员、订单归属和财务职责。验收覆盖团员既可派也可接、客户看本人订单、其他客户无法通过订单 ID 读取明细、普通团员不能修改团抽。依赖 P1-01、P1-02。
- [x] **P1-05 配置抽成并保存派发时的规则**。两项抽成均按赠送次数计算。派单人填写每次单价与首段每次派抽，获授权的管理员在抽成规则中调整每次团抽金额。验收配置界面没有计抽口径开关、接口拒绝写入按颗模式、派单人无法改写团抽，历史快照可按原语义追溯。整单锁定首段每次派抽和团抽。验收后台团抽从 0.05 调到 0.07 元/次后，原单续段仍按首段派抽和 0.05 元/次团抽，全新订单使用 0.07 元/次团抽。依赖 P1-04，计抽及抽成继承见 Q1、Q10、Q11。

## P1 · 报价、派接单与每日履约

- [x] **P1-06 报价及收款登记**。订单由独立计价的段组成，每段记录总次数、日量（次/日）和每次单价，爱心款汇总各段付费赠送次数乘对应单价。建单时另存预计实收爱心颗数。保留原报价、收款人、实收金额及时间。适配原订购颗数、段颗数和每颗价格的接口与表单，旧记录按原义追溯。验收不同单价的段可独立报价，及以 0.50 元/次报价 100 次时全程普通期预计 100 颗、全程双倍期预计 200 颗，两笔爱心款均为 50 元。普通单的 50 元爱心款和 1 元解锁款分列。依赖 P1-05，关联 Q3、Q6、Q9。
- [x] **P1-07 派单人主动派发与多人承接**。团员端可直接发起并派发订单，也可派发归属本人的客户端订单。两种来源均须主动派发后才可公开抢单或接受指派。分配接口和页面使用赠送次数，每段可指定各送心员的每日负责次数和预期执行时段。接单时按已知情况保留实际实收爱心颗数，和建单预计、实际收款分别展示。验收两人各接 50 次、同单自派自接、当单派单人改派未送次数及已送记录保留，原订单来源可追溯。改派接手人须已注册入团且具有团员或更高身份，团员可发注册邀请链接。依赖 P1-04、P1-06，客户端入口见 P1-24。
- [x] **P1-24 客户端下单与派单人归属**。老板按赠送次数下单，建单保留预计实收爱心颗数。验收老板指定与系统随机指定均限本俱乐部有效且带“派单”标记的团员。无合格候选时仍创建待分配订单，团长或副团长可选本俱乐部任一有效团员，列表置顶有效且带“派单”标记者。分配仅确定本单归属，保留成员原标记。实际分配前，老板可取消本人的待分配订单。验收同单取消与分配并发时仅一项成功，建单、取消和分配重试各自只生效一次，建单重试取回原订单且不重新选人。验收各分支均保留“客户端下单”来源和客户归属，确定派单人后可追溯老板指定、系统随机或管理者手动分配。验收拒绝跨俱乐部、非团长或副团长的分配请求及取消他人订单。分配后为待派单，由本单派单人主动派发，再触发接单和全团通知。依赖 P1-02、P1-04，数量见 P1-06，派发见 P1-07，归属规则见 Q7。
- [x] **P1-08 防止超领与重复接单**。团员申报每日可赠送次数，按领取先后分配，在段每日余量、段内及整单可领余量内截量。验收单段 100 次用 10 天完成时日量为 10 次，依次申报 5、3、5、5 次/日，实际分得 5、3、2、0 次/日。并发领取最后可领次数不会超领，重试返回一致结果，派单人能看到已领、待领次数。依赖 P1-07。
- [x] **P1-09 关联送心号并登记解锁**。每个接单人能绑定多个号，区分已有好友和新解锁，费用能追到对应老板游戏号、送心号和送心员。验收含两人各 5 个新号、已有好友及重复提交三种情况。依赖 P1-07，关联 Q3。
- [ ] **P1-10 实现日报、补报和更正**。按日、团员及游戏号登记实际赠送次数与实际到账颗数，进度及剩余按赠送次数计算，原日报颗数和更正历史可追溯。验收双倍日实际送 4 次后，日报计履约 4 次、剩余减 4 次，预计 8 颗与实际到账分列，未知实际保留未知。补报和未入账日报更正提交即生效，重复提交只计一次，更正保留前后值、经办人、时间及原因。依赖 P1-09，已入账更正关联 Q4、Q5。
- [ ] **P1-11 提供派单监督与客户进度页**。派单人按分段约定和各团员的分工窗口定位落后或漏报的份额。老板能核对本单约定、已送与剩余次数，以及预计实收和实际到账颗数。履约完成量与结单状态分别展示，未结单时可由老板在原单追加计价段。客户视图不展示其他客户订单及团员内部收入。依赖 P1-04、P1-10，结单及续单见 P1-16、P1-17。

## P1 · 活动、异常与结算

- [ ] **P1-12 实现买赠与折扣报价**。分列付费次数与促销赠送次数。先送完本单全部付费次数，再履约促销赠送次数。已履约的促销赠送正常计酬，从团费扣除赠心成本。按细则的买 100 送 5 算例，核对前 100 次为付费、后 5 次为促销赠送，以及总量 105 次、老板实付 50 元、送心报酬 42 元、派抽 5.25 元、团费收入 5.25 元及活动支出 2.50 元。折扣由本单派单人承担，优惠可超过本单派抽，无需先行补足余额。验收 100 次按 0.50 元/次原价 50 元，优惠 5 元，实付 45 元，全部履约且无解锁或其他调整，派抽 0.03 元/次、团抽 0.05 元/次时，送心报酬 42 元、团费 5 元、派抽原额 3 元、折扣支出 5 元，派单人个人净变动 −2 元，分配合计 45 元。买 100 送 5 可同时使用报价优惠，优惠只从原付费服务款扣除。验收按 0.50 元/次买 100 送 5 并优惠 5 元，实付 45 元，共履约 105 次。全部履约、派抽和团抽各 0.05 元/次且无解锁时，送心报酬为 42 元，派单人单列派抽 5.25 元和折扣支出 5 元，净增 0.25 元，团费单列团抽 5.25 元和赠心支出 2.50 元，净增 2.75 元，分配合计 45 元。依赖 P1-05、P1-06，折扣入账见 P1-17。买赠退单验收见 P1-14，折扣单部分退款的金额分配待 Q2 确认。
- [ ] **P1-13 按普通期与双倍期拆分实绩**。普通期 2 次加双倍期 2 次共履约 4 次，实际到账 6 颗时单记 6 颗。按细则验收双倍期实际送 4 次、爱心款 2 元、两项抽成各 0.20 元、送心员报酬 1.60 元。混合报价按 60 次双倍期、40 次普通期、每次 0.50 元核对预计实收 160 颗、爱心款 50 元。整单余 1 次且实际到账 2 颗时，履约计 1 次。仅到账倍率变化时差额为零。依赖 P1-05、P1-10，时段边界和超额赠送次数见 Q2。
- [ ] **P1-14 提前终止与部分退款**。老板主动退单或拒绝跨期补差时，停止后续送心并保留已履约明细。派单人提交带原因的变更，只按未送的付费次数核算应退爱心款，剩余促销赠送次数的退款金额为零，实退另记。退款暂不强制复核。用 100 次已送 80 次的普通单、原付 50 元且剩余 5 次的跨期单验收。拒补分支应退 2.50 元，退足后净收 47.50 元，实补为 0 元。接入 P1-12 后验收买 100 送 5，每次 0.50 元，无折扣、解锁或其他变更时，已送 80 次则停送 20 次付费和 5 次促销赠送，应退 10.00 元。已送 102 次则停送 3 次促销赠送，应退 0.00 元。依赖 P1-06、P1-10、P1-23，关联 Q2、Q3、Q5。
- [ ] **P1-15 分开记录客户减免与团员扣款**。每笔调整指定对象、原因、金额、审批结果和资金归属。验收一单同时发生减免和扣款时，老板实退款与责任团员实扣金额可分别追查，无重复冲减。依赖 P1-04、P1-14，待 Q5。
- [ ] **P1-16 生成预计与最终结算单**。按分段约定次数预计。最终结算对每名送心员汇总本人各段实际履约次数乘每次单价，再按本人履约次数扣除派抽和团抽。实际到账颗数、实际解锁费用及其他调整另列。履约结束且金额核平时待结单。普通单先验收 5、5、20.50、20.50 元，活动和异常接入 P1-12～P1-15、P1-23。普通单依赖 P1-05、P1-09、P1-10。
- [ ] **P1-17 确认结单并记入个人余额与团费**。本单派单人确认结单后，系统按核定明细记入派抽、送心报酬及团费。验收履约完成但尚未结单时资金未入账，其他团员无法替本单派单人确认结单。同一结算重复执行或中途失败重试，所有账户最终只记一次。接入 P1-12 后，验收折扣单分列派抽收入 3 元和整笔折扣支出 5 元，净变动 −2 元仅作汇总，派单人的结单前余额 1 元入账后为 −1 元，且重试不会重复扣款。验收未结单时老板能在原单追加计价段，包括原约定已送完的情况。新增段沿用首段每次派抽和团抽，原段价格、实绩和收款历史可追溯。已入账后的修订可追溯原记录。依赖 P1-16，结单、分段和抽成见 Q8～Q11，入账后更正关联 Q5。
- [ ] **P1-18 提供财务对账与个人明细**。按订单核对赠送次数的计价与抽成依据，分别查实收、实退、待退、待结单及个人与团费入账。团员可查自己的派单与送心收入。普通单净收 51 元与四项分配相等，可核对从核平待结单到派单人确认结单并入账的记录。买赠单分别列团抽收入、赠心成本和团费净变动，重复入账只扣一次活动成本。接入 P1-14、P1-15、P1-23 后，按细则核对部分退款净收 41 元、拒补停送退足后净收 47.50 元及减免、扣款去向。普通单依赖 P1-06、P1-17。
- [ ] **P1-23 记录已付款订单的改价**。仅跨游戏活动时段、到账倍率变化时差额为零。剩余次数的每次单价确需变更时，本单派单人提交涉及次数、原每次单价、新每次单价、拟差额、原因及协商结果。验收缺原因不能提交。原付 50 元、尚余 5 次拟由 0.50 改为 0.60 元/次的样单，验证同意且实际补付 0.50 元后续送，以及拒补停送、按原已付次数应退 2.50 元。原实收、实补、应退、实退可分别核对。依赖 P1-06、P1-10。

## P1 · 发布派单通知与团员接单区

以下为待实现方案。通知贯穿“正式发布 → 全团站内可查 → 已订阅设备收到提醒 → 点击定位订单 → 团员主动抢单”。两种订单来源复用这条流程。[业务规则](club-business.md#派单发布通知与接单区)

- [ ] **P1-25 发布事件与全员站内通知**。NestJS 在同一次持久化操作中保存“已派发”状态和待投递事件，事件带唯一发布 ID、俱乐部、订单及发布时间。例如共享订单采用 MongoDB 时，可在同一订单文档原子写入待投递事件。后台任务按发布时本俱乐部有效成员名单分发，以“发布 ID + 团员 ID”唯一写入站内通知，提供分页读取及标记已读接口。验收保存草稿、老板下单、系统选人、发布失败均无全员通知。成功一次则每人一条，包括未带“派单”标记或未订阅推送的团员。重复点击发布、投递中断后恢复均不重发站内记录。依赖 P1-02、P1-07。
- [ ] **P1-26 独立接单区与抢单接口**。团员端提供固定路由，例如 `/claim-board?noticeId=…`，也支持从导航直接进入无参数的接单区。服务端按登录团员的俱乐部、订单权限和最新状态返回订单、公开日量与可领剩余次数，以及本人获指派的份额。打开通知只定位订单，点击“抢单”才提交每日可赠送次数。复用 P1-08 的幂等键、按序截量和原子余量校验。验收双倍期申报每天可送 4 次且余量足够时分得 4 次/日，实际履约由日报更新。两人从同一通知抢最后可领的 1 次，仅一人成功，另一人看到最新状态。已抢完、撤回或无权承接时仍可浏览其他可接订单。依赖 P1-04、P1-08、P1-25。
- [ ] **P1-27 Web Push 订阅与投递**。团员点击“开启接单提醒”后，在 HTTPS 团员端注册 Service Worker、申请通知权限，并用 `PushManager.subscribe`、`userVisibleOnly` 和 VAPID 公钥获取设备订阅。NestJS 用认证接口保存 endpoint、加密所需的 `p256dh` 与 `auth`，绑定当前团员和设备订阅。服务端独占 VAPID 私钥，使用标准 Web Push 库按每位收件人的有效订阅加密发送。以“发布 ID + 订阅 ID”跟踪发送，限流或临时故障在有效期内退避重试，失效订阅（404/410）停用。关闭提醒、退出或切换账号时解除或重新核验设备绑定。验收多设备均可接收、其他俱乐部收不到，失败的推送不影响订单发布和站内通知。依赖 P1-19、P1-25。[Web Push 协议](https://www.rfc-editor.org/rfc/rfc8030)
- [ ] **P1-28 系统通知展示、点击回跳与真机验收**。Service Worker 在 `push` 中调用 `showNotification`，以发布 ID 生成通知 tag，锁屏文案只提示“有新派单，点击进入接单区”。在 `notificationclick` 中关闭通知，使用 `event.waitUntil` 聚焦并导航已有团员端窗口，或用 `clients.openWindow` 打开团员端同源接单区。会话失效时先登录，再回到目标订单并重新鉴权。团员回到前台时刷新站内未读与接单列表。用团员常用的安卓手机和网络，以及已添加到主屏幕的 iPhone/iPad，实测前台、锁屏、页面关闭、拒绝授权及断网恢复。分别核对站内生成、推送服务受理、设备实际展示和点击结果。依赖 P1-26、P1-27。[通知点击事件](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope/notificationclick_event) · [iOS 与 iPadOS Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

## P2 · 代跑

- [ ] **P2-01 收集实际样单并确认规则**。取得一笔普通单、一笔取消或争议单，明确委托的服务、定价单位、接单交接、完成凭据、验收与退款。完成条件是业务方能按样单算出老板应付和各方应得。
- [ ] **P2-02 接入代跑业务流程**。基于已确认样单，为三端增加代跑下单或代录、派接、履约记录和结果确认，沿用俱乐部权限与订单查询。依赖 P2-01、P1 共用订单能力。
- [ ] **P2-03 核对代跑结算并验收**。按确认的规则接入资金流水，在手机、Pad 和桌面验证普通及异常样单，回归已有送心订单金额。依赖 P2-02、P1-17。

## P3 · 陪玩

- [ ] **P3-01 收集实际样单并确认规则**。核对老板购买内容、是否预约、服务开始与结束的认定、计价、取消及争议。用一笔普通单和一笔异常单确认验收凭据和各方应得。
- [ ] **P3-02 接入陪玩业务流程**。按调研结果实现三端需求登记、派接、服务记录及验收，使用共同的成员与订单权限。依赖 P3-01、P1 共用订单能力。
- [ ] **P3-03 核对陪玩结算并验收**。用确认的样单将实收、退款、团员收益和团费对账，在三类设备走查，回归送心与代跑。依赖 P3-02、P1-17。
