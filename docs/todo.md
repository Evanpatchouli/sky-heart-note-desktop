## P1 · 俱乐部共用基础

- [ ] **P1-01 确认职责与订单权限表**。列出老板、派单人、接单人、团长、副团长和财务能读写的内容，记录同单自接与异常审核决定。验收用同一团员在两笔订单互换派/接身份走查。关联 Q4～Q6。
- [ ] **P1-02 建立俱乐部共享订单与成员关系**。订单来源固定为“直接派单”或“客户端下单”。分别记录创建人、客户及游戏账号、本单派单人、实际派发状态、接单份额和执行账号，以及业务类型。俱乐部成员可带“派单”身份标记。验收不同团员按授权协作，老板可查看自己的多笔订单，两种来源可分别查询。依赖 P1-01。
- [ ] **P1-03 制定旧个人库迁移与核对方案**。以原所有者及本地记录 ID 标识来源。处理跨库同号、文本派单人、无法匹配老板或成员的记录。验收用两份同 ID 的旧库演练，列出需人工认领的项，重复导入不重单，旧“实际结算”字段不会直接增加余额。依赖 P1-02。
- [ ] **P1-04 落实业务对象级授权**。服务端校验俱乐部成员、订单归属和财务职责。验收覆盖团员既可派也可接、客户看本人订单、其他客户无法通过订单 ID 读取明细、普通团员不能修改团抽。依赖 P1-01、P1-02。
- [ ] **P1-05 配置抽成并保存派发时的规则**。后台以一个开关为派抽、团抽共同选择按到账颗数或按赠送次数计抽。派单人填写单价与派抽，团抽取后台配置。验收拒绝两项口径混配、拒绝派单人改写团抽，并验证后台切换口径后仅新派发订单采用新配置。依赖 P1-04，额外费率形式见 Q1。

## P1 · 报价、派接单与每日履约

- [ ] **P1-06 报价及收款登记**。以到账颗数计价，按各时段预计到账颗数乘对应单价报价，老板在派单时按此价付款。保留原报价、收款人、实收金额及时间。验收同样购买 200 颗，全程双倍期按 0.35 元/颗收 70 元，普通期按 0.50 元/颗收 100 元。另验收 100 颗普通单的 50 元爱心款和 1 元解锁款分列。依赖 P1-05，关联 Q3、Q6。
- [ ] **P1-07 派单人主动派发与多人承接**。团员端可直接发起并派发订单，也可派发归属本人的客户端订单。两种来源均须完成派发，随后才允许公开抢单或由指定的送心员承接。验收未派发的订单不可接，派发后可将 100 颗分给两人各承担 50 颗，原订单来源保持可追溯。依赖 P1-04、P1-06，客户端入口见 P1-24。
- [ ] **P1-24 客户端下单与派单人归属**。老板下单时若指定了派单人，则由该人负责。未指定时，系统从本俱乐部带“派单”标记的团员中随机指定一位。验收两种情形均创建“客户端下单”来源的订单，重复提交同一次请求不重复建单或重新选人。由本单派单人进入团员端完成 P1-07。依赖 P1-02、P1-04，候选为空等边界见 Q7。
- [ ] **P1-08 防止超领与重复接单**。最后一个可领份额被并发领取时，只有有效份额成交。重试返回一致结果，派单人能看到已领、待领数量。依赖 P1-07。
- [ ] **P1-09 关联送心号并登记解锁**。每个接单人能绑定多个号，区分已有好友和新解锁，费用能追到对应老板游戏号、送心号和送心员。验收含两人各 5 个新号、已有好友及重复提交三种情况。依赖 P1-07，关联 Q3。
- [ ] **P1-10 实现日报、补报和更正**。按日、团员及游戏号登记赠送次数与实际到账颗数，用到账颗数扣减剩余量。验收双倍日 1 次到账 2 颗只记 1 次操作、剩余减 2。重复提交不重复扣减，更正能追到前后差异与原因。依赖 P1-09，关联 Q4。
- [ ] **P1-11 提供派单监督与客户进度页**。派单人能定位落后于约定工期的份额与漏报日期。老板能核对本单的承诺、到心与剩余量。客户视图不展示其他客户订单及团员内部收入。依赖 P1-04、P1-10。

## P1 · 活动、异常与结算

- [ ] **P1-12 实现买赠与折扣报价**。分列付费与赠送颗数，实际到账的赠心正常计酬，从团费扣除赠心成本。按细则的买 100 送 5 算例，核对老板实付 50 元、送心报酬 42 元、派抽 5.25 元、团费收入 5.25 元及活动支出 2.50 元。依赖 P1-05、P1-06，折扣及活动叠加规则见 Q2。
- [ ] **P1-13 按普通期与双倍期拆分实绩**。普通期 2 次加双倍期 2 次，合计 4 次、到账并抵扣 6 颗。按细则中的验收参数，70 元双倍单的两项抽成均按颗或均按次时，送心员分别得 50 元、60 元。涵盖两个时段的 120 颗双倍加 80 颗普通订单应报 82 元。履约偏离产生的差价列作拟变更。依赖 P1-05、P1-10，时段边界和超额交付见 Q2。
- [ ] **P1-14 提前终止与部分退款**。老板主动退单或拒绝跨期补差时，暂停后续送心并保留已履约份额。派单人提交带原因的变更，分别登记应退和实退。用 100 颗已送 80 颗的普通单和已付 70 元后拒补的跨期单验收，拒补分支不产生补差收入。依赖 P1-06、P1-10、P1-23，关联 Q2、Q3、Q5。
- [ ] **P1-15 分开记录客户减免与团员扣款**。每笔调整指定对象、原因、金额、审批结果和资金归属。验收一单同时发生减免和扣款时，老板实退款与责任团员实扣金额可分别追查，无重复冲减。依赖 P1-04、P1-14，待 Q5。
- [ ] **P1-16 生成预计与最终结算单**。对每名送心员汇总本人实际到账颗数乘以各段对应单价，再减去归属于本人的派抽和团抽。实际解锁费用及其他调整另列。普通单先验收 5、5、20.50、20.50 元，活动和异常接入 P1-12～P1-15、P1-23。普通单依赖 P1-05、P1-09、P1-10。
- [ ] **P1-17 个人余额与团费入账**。结算明细关联订单与资金流水。同一结算重复执行或中途失败重试，所有账户最终只记一次。已入账后的修订可追溯原记录。依赖 P1-16，关联 Q5。
- [ ] **P1-18 提供财务对账与个人明细**。按订单核对实收、实退、待退、待结、个人及团费入账，团员可查自己的派单与送心收入。普通单依赖 P1-06、P1-17，验收净收 51 元与四项分配相等。买赠单分别列团抽收入、赠心成本和团费净变动，重复结算只扣一次活动成本。接入 P1-14、P1-15 后，按细则核对净收 41 元的部分退款样例及减免、扣款去向。
- [ ] **P1-23 记录已付款订单的改价**。本单派单人提交涉及数量、原价、新价、差额和变更原因，并记录与老板协商的结果。验收缺原因不能提交。对原付 70 元、尚余 10 颗需跨期的样单，分别验证老板同意并补付 1.50 元后续送，以及老板拒补后暂停送心并退款。原实收、实补、实退可分别核对。依赖 P1-06、P1-10。

## P1 · 三端 PWA、触屏与发布验收

- [ ] **P1-19 三端可独立安装、启动和更新**。分别配置 manifest、名称、图标、启动 URL 与范围，设计 Service Worker 的静态资源更新和断网提示。涉及收款、抢单、结算的请求只在服务端确认后显示成功。验收在 Android 手机和 iPhone/iPad 上安装并独立启动，覆盖版本更新、断网恢复和切换账号后的数据隔离。
- [ ] **P1-20 团员端、客户端手机底部 Tab**。两端的一级导航均使用底部 Tab。团员端设独立“接单”Tab，与通知打开同一接单区。验收在手机上从底栏到达接单区、老板下单入口和各自的订单，返回后保留上下文，软键盘和底部安全区不遮挡提交。依赖 P1-07、P1-11、P1-24、P1-26。
- [ ] **P1-21 管理端手机适配与三端 Pad 触控适配**。让报价、领取、逐日填报、客户查单、财务明细和审批按屏宽调整布局。为必要的悬停或拖拽操作提供点击入口。验收覆盖管理端手机及三端 Pad 横竖屏，无鼠标可完成各自业务。同时回归桌面键盘与鼠标操作。依赖 P1-11、P1-18。
- [ ] **P1-22 发布前走查**。用老板、派单人、两名送心员与管理/财务身份验证两种来源均经主动派发后才能接单，贯穿普通单、活动单及异常单。实测通知点击进入接单区、手机底栏直接进入、并发争抢最后一个份额。记录设备、浏览器、三端安装态和跨端借用结果，包括无可借用会话时的密码登录。覆盖重复日报、重复结算、历史规则复算、派单人改价留因和越权拒绝。依赖 P1-08、P1-12～P1-21、P1-23～P1-28。

## P1 · 发布派单通知与团员接单区

以下为待实现方案。通知贯穿“正式发布 → 全团站内可查 → 已订阅设备收到提醒 → 点击定位订单 → 团员主动抢单”。两种订单来源复用这条流程。[业务规则](club-business.md#派单发布通知与接单区)

- [ ] **P1-25 发布事件与全员站内通知**。NestJS 在同一次持久化操作中保存“已派发”状态和待投递事件，事件带唯一发布 ID、俱乐部、订单及发布时间。例如共享订单采用 MongoDB 时，可在同一订单文档原子写入待投递事件。后台任务按发布时本俱乐部有效成员名单分发，以“发布 ID + 团员 ID”唯一写入站内通知，提供分页读取及标记已读接口。验收保存草稿、老板下单、系统选人、发布失败均无全员通知。成功一次则每人一条，包括未带“派单”标记或未订阅推送的团员。重复点击发布、投递中断后恢复均不重发站内记录。依赖 P1-02、P1-07。
- [ ] **P1-26 独立接单区与抢单接口**。团员端提供固定路由，例如 `/claim-board?noticeId=…`，也支持从导航直接进入无参数的接单区。服务端按登录团员的俱乐部、订单权限和最新状态返回订单、公开剩余份额及本人获指派的份额。打开通知只定位订单，点击“抢单”才提交领取请求。复用 P1-08 的幂等键和原子余量校验。验收两人从同一通知抢最后一个份额，仅一人成功，另一人看到最新状态。已抢完、撤回或无权承接时仍可浏览其他可接订单。依赖 P1-04、P1-08、P1-25。
- [ ] **P1-27 Web Push 订阅与投递**。团员点击“开启接单提醒”后，在 HTTPS 团员端注册 Service Worker、申请通知权限，并用 `PushManager.subscribe`、`userVisibleOnly` 和 VAPID 公钥获取设备订阅。NestJS 用认证接口保存 endpoint、加密所需的 `p256dh` 与 `auth`，绑定当前团员和设备订阅。服务端独占 VAPID 私钥，使用标准 Web Push 库按每位收件人的有效订阅加密发送。以“发布 ID + 订阅 ID”跟踪发送，限流或临时故障在有效期内退避重试，失效订阅（404/410）停用。关闭提醒、退出或切换账号时解除或重新核验设备绑定。验收多设备均可接收、其他俱乐部收不到，失败的推送不影响订单发布和站内通知。依赖 P1-19、P1-25。[Web Push 协议](https://www.rfc-editor.org/rfc/rfc8030)
- [ ] **P1-28 系统通知展示、点击回跳与真机验收**。Service Worker 在 `push` 中调用 `showNotification`，以发布 ID 生成通知 tag，锁屏文案只提示“有新派单，点击进入接单区”。在 `notificationclick` 中关闭通知，使用 `event.waitUntil` 聚焦并导航已有团员端窗口，或用 `clients.openWindow` 打开团员端同源接单区。会话失效时先登录，再回到目标订单并重新鉴权。团员回到前台时刷新站内未读与接单列表。用团员常用的安卓手机和网络，以及已添加到主屏幕的 iPhone/iPad，实测前台、锁屏、页面关闭、拒绝授权及断网恢复。分别核对站内生成、推送服务受理、设备实际展示和点击结果。依赖 P1-26、P1-27。[通知点击事件](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope/notificationclick_event) · [iOS 与 iPadOS Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

## P2 · 代跑

- [ ] **P2-01 收集实际样单并确认规则**。取得一笔普通单、一笔取消或争议单，明确委托的服务、定价单位、接单交接、完成凭据、验收与退款。完成条件是业务方能按样单算出老板应付和各方应得。
- [ ] **P2-02 接入代跑业务流程**。基于已确认样单，为三端增加代跑下单或代录、派接、履约记录和结果确认，沿用俱乐部权限与订单查询。依赖 P2-01、P1 共用订单能力。
- [ ] **P2-03 核对代跑结算并验收**。按确认的规则接入资金流水，在手机、Pad 和桌面验证普通及异常样单，回归已有送心订单金额。依赖 P2-02、P1-17。

## P3 · 陪玩

- [ ] **P3-01 收集实际样单并确认规则**。核对老板购买内容、是否预约、服务开始与结束的认定、计价、取消及争议。用一笔普通单和一笔异常单确认验收凭据和各方应得。
- [ ] **P3-02 接入陪玩业务流程**。按调研结果实现三端需求登记、派接、服务记录及验收，使用共同的成员与订单权限。依赖 P3-01、P1 共用订单能力。
- [ ] **P3-03 核对陪玩结算并验收**。用确认的样单将实收、退款、团员收益和团费对账，在三类设备走查，回归送心与代跑。依赖 P3-02、P1-17。
