# 俱乐部平台开发任务

按[路线图](roadmap.md)逐项追踪。每项有固定编号，提交或 PR 可引用该编号。开始任务时可追加负责人或 PR 链接。达到所列验收条件后勾选。涉及未定规则的任务引用[送心决定 Q1～Q6](heart-delivery.md)，可先完成普通单部分。

## 可复用的现状

- [x] **B-01 三端身份基础**。已有按端准入、角色校验、显式跨端借用和退出。已有[登录集成测试](../server/test/web-apps.e2e.mjs)。
- [x] **B-02 个人送心记录**。已有个人预约和送心号 CRUD、时间轴及旧桌面 SQLite 导入。现有[个人数据测试](../server/src/modules/employee/employee.spec.ts)可作为兼容性回归。

## P1 · 俱乐部共用基础

- [ ] **P1-01 确认职责与订单权限表**。列出老板、派单人、接单人、团长、副团长和财务能读写的内容，记录同单自接与异常审核决定。验收用同一团员在两笔订单互换派/接身份走查。关联 Q4～Q6。
- [ ] **P1-02 建立俱乐部共享订单与成员关系**。记录业务类型、客户及其游戏账号、派单人、接单份额和执行账号。验收用两个团员登录读取同一笔获授权的订单，老板可以关联多笔自己的订单。依赖 P1-01。
- [ ] **P1-03 制定旧个人库迁移与核对方案**。以原所有者及本地记录 ID 标识来源。处理跨库同号、文本派单人、无法匹配老板或成员的记录。验收用两份同 ID 的旧库演练，列出需人工认领的项，重复导入不重单，旧“实际结算”字段不会直接增加余额。依赖 P1-02。
- [ ] **P1-04 落实业务对象级授权**。服务端校验俱乐部成员、订单归属和财务职责。验收覆盖团员既可派也可接、客户看本人订单、其他客户无法通过订单 ID 读取明细、普通团员不能修改团抽。依赖 P1-01、P1-02。
- [ ] **P1-05 配置团抽并保存报价依据**。后台维护团抽及适用条件。派单表单填写爱心单价和派抽，显示服务端给出的团抽。验收时派单人尝试改写团抽必须被服务端拒绝，后台调价后仍能复算原订单。依赖 P1-04，关联 Q1。

## P1 · 报价、派接单与每日履约

- [ ] **P1-06 报价及收款登记**。派单人录入老板需求、购买量、期望工期，区分预估爱心款、解锁款和实收。记录收款人、金额、时间。验收能分别查到示例的 50 元爱心款、1 元解锁款和 51 元总实收。依赖 P1-05，关联 Q3、Q6。
- [ ] **P1-07 发布、指派和多人承接**。支持公开可抢的订单及指定团员的订单，记录每个人的份额与接单结果。验收一笔 100 颗的订单可由两人各承担 50 颗。依赖 P1-04、P1-06。
- [ ] **P1-08 防止超领与重复接单**。最后一个可领份额被并发领取时，只有有效份额成交。重试返回一致结果，派单人能看到已领、待领数量。依赖 P1-07。
- [ ] **P1-09 关联送心号并登记解锁**。每个接单人能绑定多个号，区分已有好友和新解锁，费用能追到对应老板游戏号、送心号和送心员。验收含两人各 5 个新号、已有好友及重复提交三种情况。依赖 P1-07，关联 Q3。
- [ ] **P1-10 实现日报、补报和更正**。按日、团员及游戏号登记操作次数与实际到账，汇总全单进度。留存修改原因和前后差异。验收同一次双击提交不会翻倍，更正某号的记录仅改变相关汇总。依赖 P1-09，关联 Q4。
- [ ] **P1-11 提供派单监督与客户进度页**。派单人能定位落后于约定工期的份额与漏报日期。老板能核对本单的承诺、到心与剩余量。客户视图不展示其他客户订单及团员内部收入。依赖 P1-04、P1-10。

## P1 · 活动、异常与结算

- [ ] **P1-12 实现买赠与折扣报价**。区分付费和赠送量，保存优惠、折扣承担方及计酬依据。验收分别用买 100 送 5 和业务方确认的折扣单核对老板应付与分账。依赖 P1-05、P1-06，待 Q2。
- [ ] **P1-13 按普通期与双倍期拆分实绩**。同单普通期 2 次、双倍期 2 次应记录 4 次操作、到账 6 颗。两个时段的应收与各方收益可分别复算。依赖 P1-05、P1-10，待 Q2。
- [ ] **P1-14 提前终止与部分退款**。冻结未履约份额，计算可退金额，登记实退。可核对已送、已收、已退和待结金额。用 100 颗已送 80 颗的例子验收普通单，再验证带优惠或解锁的变体。依赖 P1-06、P1-10，关联 Q2、Q3、Q5。
- [ ] **P1-15 分开记录客户减免与团员扣款**。每笔调整指定对象、原因、金额、审批结果和资金归属。验收一单同时发生减免和扣款时，老板实退款与责任团员实扣金额可分别追查，无重复冲减。依赖 P1-04、P1-14，待 Q5。
- [ ] **P1-16 生成预计与最终结算单**。用确认后的日报、各时段价格、实际解锁和核定调整，逐人列出送心收益，单列派抽和团费。普通单先验收 5、5、20.50、20.50 元。活动和异常分别接入 P1-12～P1-15。普通单依赖 P1-05、P1-09、P1-10。
- [ ] **P1-17 个人余额与团费入账**。结算明细关联订单与资金流水。同一结算重复执行或中途失败重试，所有账户最终只记一次。已入账后的修订可追溯原记录。依赖 P1-16，关联 Q5。
- [ ] **P1-18 提供财务对账与个人明细**。按订单核对实收、实退、待退、待结、个人及团费入账。团员查看自己的派单和送心收入。普通单依赖 P1-06、P1-17，验收净收 51 元与四项分配相等。接入 P1-14、P1-15 后，再验证部分退款样例按细则约定核到 41 元，以及减免与扣款的去向。

## P1 · 三端 PWA、触屏与发布验收

- [ ] **P1-19 三端可独立安装、启动和更新**。分别配置 manifest、名称、图标、启动 URL 与范围，设计 Service Worker 的静态资源更新和断网提示。涉及收款、抢单、结算的请求只在服务端确认后显示成功。验收在 Android 手机和 iPhone/iPad 上安装并独立启动，覆盖版本更新、断网恢复和切换账号后的数据隔离。
- [ ] **P1-20 团员端、客户端手机底部 Tab**。两端的一级导航均使用底部 Tab。保留订单内部的视图选择。验收在手机上从底栏找到团员的派接单入口、个人订单和客户本人的订单，返回后保留上下文，软键盘和底部安全区不遮挡提交。依赖 P1-07、P1-11。
- [ ] **P1-21 管理端手机适配与三端 Pad 触控适配**。让报价、领取、逐日填报、客户查单、财务明细和审批按屏宽调整布局。为必要的悬停或拖拽操作提供点击入口。验收覆盖管理端手机及三端 Pad 横竖屏，无鼠标可完成各自业务。同时回归桌面键盘与鼠标操作。依赖 P1-11、P1-18。
- [ ] **P1-22 发布前走查**。用独立老板、派单人、两名送心员和管理/财务身份贯穿普通单、活动单及异常单。记录实际设备与浏览器、三端安装态和跨端借用结果，包括无可借用会话时的密码登录。覆盖并发抢单、重复日报、重复结算和越权拒绝。依赖 P1-08、P1-12～P1-21。

## P2 · 代跑

- [ ] **P2-01 收集实际样单并确认规则**。取得一笔普通单、一笔取消或争议单，明确委托的服务、定价单位、接单交接、完成凭据、验收与退款。完成条件是业务方能按样单算出老板应付和各方应得。
- [ ] **P2-02 接入代跑业务流程**。基于已确认样单，为三端增加代跑下单或代录、派接、履约记录和结果确认，沿用俱乐部权限与订单查询。依赖 P2-01、P1 共用订单能力。
- [ ] **P2-03 核对代跑结算并验收**。按确认的规则接入资金流水，在手机、Pad 和桌面验证普通及异常样单，回归已有送心订单金额。依赖 P2-02、P1-17。

## P3 · 陪玩

- [ ] **P3-01 收集实际样单并确认规则**。核对老板购买内容、是否预约、服务开始与结束的认定、计价、取消及争议。用一笔普通单和一笔异常单确认验收凭据和各方应得。
- [ ] **P3-02 接入陪玩业务流程**。按调研结果实现三端需求登记、派接、服务记录及验收，使用共同的成员与订单权限。依赖 P3-01、P1 共用订单能力。
- [ ] **P3-03 核对陪玩结算并验收**。用确认的样单将实收、退款、团员收益和团费对账，在三类设备走查，回归送心与代跑。依赖 P3-02、P1-17。
