# 俱乐部业务说明

本平台服务于《光遇》俱乐部。老板提出需求并支付报酬，团员组织和交付服务，俱乐部管理订单、团员收益与团费。送心团可以只经营送心。俱乐部还可以经营代跑、陪玩。首期围绕一个俱乐部把送心流程跑通，再逐条接入其他业务线。

本文用“已明确”记录业务方给出的规则，用“建议”标记首版产品设计，用“待确认”标记仍会影响开发或金额的决定。送心的报价、日报、异常和结算算例见[送心业务细则](heart-delivery.md)。交付顺序见[路线图](roadmap.md)，开发进度以[任务清单](todo.md)为准。

## 订单来源

**订单来源只有两种，由谁在哪一端发起决定。派单是两种来源共同的必经环节。**

| 订单来源 | 谁发起 | 谁负责派单 | 如何进入接单流程 |
| --- | --- | --- | --- |
| 直接派单 | 派单人在团员端发起订单 | 发起订单的派单人 | 派单人在团员端主动派发，开放抢单或指派执行团员 |
| 客户端下单 | 老板在客户端提交订单 | 老板已指定时由指定的派单人负责。未指定时，系统从本俱乐部带有“派单”身份标记的团员中随机指定一位 | 订单先等待该派单人处理。由其主动派发后，才开放抢单或交给指定的执行团员 |

订单详情与统计始终沿用创建时的来源。例如，老板在客户端下单，系统指定青禾负责，青禾随后在团员端发布，这笔订单从下单到结算都归为**客户端下单**。订单另行记录派单人、其确定方式和实际派发状态，便于追溯。

## 谁在一笔订单中做什么

| 身份或分工 | 已明确的职责 | 产品需要区分的事情 |
| --- | --- | --- |
| 老板（客户） | 向派单人提出需求，或在客户端自行下单并可指定派单人。提供接受服务的游戏账号、付款，必要时申请退款 | 平台客户身份和游戏账号分别记录，老板可以查看本人从两种来源产生的订单 |
| 团长、副团长 | 参与俱乐部管理 | 具体哪些管理操作可以委派，哪些金额调整需要复核，待确认 |
| 财务 | 参与俱乐部财务管理 | 建议提供收退款核对、订单分账和团费明细。实际收款人、经办人、审核人应可区分 |
| 派单员（本单的派单人） | 发展老板、对接需求、按系统预计价收款、派单与监督进度。跨期需补差时，提交变更、说明原因并与老板协商，同意则补款续送，拒绝则停送退款 | 派单人设置派抽，管理员设置团抽。两项抽成共用后台选定的计量口径，配置变更仅用于新派发的订单 |
| 送心员（本单的接单人） | 抢单或接受指派，使用自己的送心号给老板送心，按日提交实际完成情况 | 一单可由多人承接，一人可用多个游戏号。个人收益要能追溯到本人在订单中的实际交付 |

**每个团员都可以派单和接单。** “派单”身份标记用于确定客户端订单未指定派单人时的随机候选范围。派单人、接单人应记录在具体订单上。同一团员可以在甲单派单、在乙单接单。能否接自己派出的同一单，仍需业务方确认。团长、副团长、财务是组织分工，现有 `admin`、`employee`、`common` 是端的登录权限。具体记录的读写权限取决于俱乐部成员身份、订单关系及管理授权。

## 三条业务线如何共用平台

| 优先级 | 业务线 | 已确定的边界 |
| --- | --- | --- |
| P1 | 送心 | 报价与收款、抢单或指派、游戏号解锁、每日送心、活动、异常及最终分账 |
| P2 | 代跑 | 先向业务方取得普通单和异常单，再确定服务范围、报价单位、执行记录、验收及结算方式 |
| P3 | 陪玩 | 先取得实际接单和交付案例，再确定预约、计价、履约及异常处理规则 |

建议三条业务线共用俱乐部成员、客户、订单编号、派单人与接单人关系、收退款记录、结算明细和余额流水。订单带业务类型。爱心颗数、蜡烛、送心号和好友解锁属于送心明细。代跑和陪玩的计价单位、交付凭据及状态在各自调研完成后定义。

## 三端与设备

P1 同时覆盖直接派单和客户端下单。在线支付渠道和余额提现方式待确认。

| 端 | P1 的主要操作 | 设备要求 |
| --- | --- | --- |
| 管理端 `admin` | 维护成员与授权、团抽规则。按职责监督订单、处理异常、核对结算与团费 | PC、手机、Pad 均能操作，支持安装为 PWA。小屏表格可切为摘要和详情 |
| 团员端 `employee` | 直接派单，处理分给自己的客户端订单，报价、收款登记、主动派发，抢单或接受指派、填日报、查个人余额 | PC、手机、Pad 均能操作，支持安装为 PWA。手机用底部 Tab 进入派接单、我的订单和个人入口 |
| 客户端 `client` | 提交订单，可指定派单人，查看本人订单的派发状态、活动报价、交付进度及收退款结果 | PC、手机、Pad 均能操作，支持安装为 PWA。手机用底部 Tab 到达下单、查看本人订单和个人入口 |
| 官网 `site` | 面向访客展示俱乐部及服务入口 | 保持公开访问。本轮 PWA 安装范围是上面三个登录端 |

三端移动版采用可安装的渐进式 Web 应用（PWA），原生手机 App 暂缓。底部 Tab 指手机端的**一级导航**。时间轴、列表、日历等可以继续作为订单内部的视图切换。建议在 Pad 横竖屏分别验证派单表单、多人分配和财务明细。关键操作要能点按，悬停提示要有可点开的等价入口，拖拽若用于分配则提供点选路径。手机底栏为系统安全区留空间，软键盘收起前后都能完成提交。Tab 名称和数量可在原型验证后调整。
