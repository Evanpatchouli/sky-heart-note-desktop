# 技术决策

新增重要技术决策时，可独立记录状态、背景、备选方案、取舍、影响和验证。以下是代码已采用的决策。

| 决策 | 影响与依据 |
| --- | --- |
| 四个前端共享 API | 各角色有独立入口，账户和订单数据由同一个服务管理。送心规则可由 API 和前端共同调用。[应用结构](../architecture/README.md) · [共享规则](../../common/src/club-pricing.ts) |
| 俱乐部订单和个人 SQLite 分开持久化 | 多角色协作用共享订单，原个人库继续按用户隔离，导入保留旧 ID 和关联。[个人数据导入](../../README.md#团员数据与旧库导入) |
| 新订单按赠送次数结算，保留历史按颗协议 | 报价与履约统一按次，到账倍率单独统计。历史记录按原口径查询和结算。[已确认的业务决定](../heart-delivery.md#送心业务已确认的决定) · [现有协议](../club-orders.md#业务口径与现有协议) |
| PWA 只缓存公开构建资源 | 业务数据始终由 API 实时读取，换账号时不会从离线缓存加载前一账号的订单。[Service Worker](../../common/pwa/worker.js) · [PWA 测试](../../scripts/test-pwa.mjs) |
