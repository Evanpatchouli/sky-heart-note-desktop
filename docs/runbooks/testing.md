# 测试与验收

在仓库根目录执行 `pnpm install --frozen-lockfile`，首次验证从 `pnpm build` 开始。共享包类型检查用 `pnpm --dir common typecheck`，管理端 lint 用 `pnpm --dir admin lint`。服务端的 `lint` 自带 `--fix`，单独检查可运行 `pnpm --dir server exec eslint "src/**/*.ts"`。

| 命令 | 覆盖 |
| --- | --- |
| `pnpm build` | 各工作区构建、前端 TypeScript 编译和三端 PWA 生成 |
| `pnpm test` | 服务端 Jest 和团员端待确认领取记录 |
| `pnpm test:pwa` | 已构建三端的安装元数据、离线页、缓存更新和通知路由 |
| `pnpm --dir server test:e2e` | HTTP 生产入口、跨端会话及俱乐部业务集成 |
| `pnpm --dir admin build:prototype` | 管理端设计原型的独立构建 |

HTTP 集成需要已构建的 `server/dist` 和本机可运行的 `mongod`。测试在临时目录和端口启动数据库及 API。若 `mongod` 不在 PATH，设置 `$env:MONGOD_BINARY` 为可执行文件的绝对路径。可运行 `pnpm --dir server exec node --test test/web-apps.e2e.mjs` 单独验证多端入口。

品牌、PWA 或工作区元数据变更至少核对构建、PWA 和多端 HTTP 测试。订单规则变更用[上下文索引](../context/README.md)定位测试，同步核对权限及历史订单分支。部署配置变更按照[发布检查](deployment.md#发布检查与回滚)校验 Compose。

## 真机验证

用 Android Chrome 及 iPhone/iPad 主屏幕应用验证三端安装、版本更新、断网恢复和账号隔离。开启设备提醒后核对目标端、切换账号及点击通知后的落点。[安装与设备提醒步骤](../../README.md#安装管理端团员端和客户端)

## 2026-11-26 模拟设备验收

本轮使用隔离的测试账号、临时 MongoDB 和生产构建。设备验收按委托采用模拟环境。正式发布前仍需在实际 Android 手机和 iPhone/iPad 核对主屏幕图标、独立启动及系统通知表现。

| 环境 | 已验证 |
| --- | --- |
| Windows Chrome 157，独立测试配置 | 管理、团员、客户端分别安装并从应用窗口启动，窗口的 `display-mode` 为 `standalone`。发布下一版 Worker 后，旧窗口收到更新提示。关闭该端全部窗口、重新打开，新的静态缓存生效，旧缓存移除。三端各切换一次真实测试账号，服务端返回新账号，推送绑定随之切换，离线缓存中无 API 响应。 |
| Android 16 模拟器，Chrome 134 | 三端安装清单均通过浏览器安装检查。三端「添加到主屏幕」均出现对应的安装操作。断开测试站点后，三端显示各自离线页，恢复站点后可重新加载。模拟环境未确认 Android 系统生成 WebAPK。 |
| Playwright WebKit 26.5，iPhone 13、iPad Pro 11 配置 | 两类设备配置各走通三端清单读取、Service Worker 激活、服务中断时离线页及恢复访问。iOS/iPadOS 主屏幕安装及系统锁屏需用 Apple 设备复验。 |

**三端触控。** 管理端在手机 390×844 和两种 Pad 方向打开导航、结算清单及账单依据。团员端在 768×1024 调整本人排期、提交 10 次到账 9 颗的日报，并切换五种承接视图核对，原派接窗口保留。1024×768 横屏保存 10 元报价并领取 20 次。客户端在 820×1180、1180×820 提交 12 次订单，按来源查回详情，核对另一单从零履约到 50 次、到账 50 颗直至结单。手机窗口模拟软键盘收起底栏后仍可提交。桌面使用键盘与鼠标回归导航、下单、订单详情及视图切换。

**Web Push 订阅与投递。** 在本地 HTTPS 的团员端，从通知窗口开启系统提醒。模拟浏览器订阅提供设备密钥，UI 使用 `userVisibleOnly` 和 VAPID 公钥，真实认证接口绑定当前账号及应用。关闭后核对数据库已解除订阅。HTTP 集成用独立密钥分别解密两台模拟设备的投递，同时验证 429 退避和重启续投、404/410 停用、换号隔离、客户端接待定向与全团派发。推送网关故障时，订单及站内通知仍可查。

**系统提醒与回跳。** 在 Android 16 模拟器中通过浏览器调试接口向生产 Service Worker 注入派发消息，检查 Android 通知栏后实际点按。前台、锁屏后解锁、业务页面关闭三种情况均进入对应订单的接单区。在服务中断时点击同一类提醒会显示离线页，恢复后重载保留原单定位。接待通知点入派单页，服务端重新核验通知，并预选该客户的 17 次订单。没有会话的浏览器从同一定位链接完成密码和验证码登录后回到原单。拒绝系统权限时，站内通知和接单区仍可用。Apple 系统通知展示、APNs 到机和锁屏点按留作真机复验。

### P1 发布前走查

使用临时 MongoDB 8.2 和生产 API，按老板、派单人、两名送心员、团长或副团长、财务分别操作。自动化 HTTP 全量运行 70 项通过。服务端单元测试 8 项、团员端领取记录测试 2 项及生产 PWA 测试 10 项通过。

| 走查 | 结果与可复验入口 |
| --- | --- |
| 两种来源与最后一份 | 直接派单及客户下单均须主动发布才能领取。两实例同时处理四个团员的请求并各自重试，最后 1 次的分配结果为 0、0、0、1，重试返回本人原凭据。[派接单验收](../../server/test/club-gift-dispatch.e2e.mjs) |
| 正常单、活动单与异常单 | 普通单 50 元与四项分配核平，三优惠订单净收 40 元、履约 105 次。拒补停送的实际补款为 0 元，退足后净收 47.50 元。旧规则可按原计算单复查。重复日报、重复结单与其他团员越权结单均有断言。[结算](../../server/test/club-settlement.e2e.mjs) · [结单与更正](../../server/test/club-settlement-close.e2e.mjs) · [改价留因](../../server/test/club-price-adjustment.e2e.mjs) |
| 运营值班 | 从手机底栏进入接单区，派单通知也定位同一入口。管理端从首页履约次数进入对应清单、单笔订单及账单，另一端结单后待结数和团费自行更新。[运营仪表盘](../../server/test/club-dashboard.e2e.mjs) |
| 跨端会话 | 本地 HTTPS 浏览器用密码及验证码登录团员端，分别在客户端和管理端看到可借用账号；显式选择后，三端服务端会话返回同一短 ID。无候选的独立浏览器可密码登录并回到原通知。退出、过期与撤权按会话重新校验。[跨端授权](../../server/test/web-apps.e2e.mjs) |

### 代跑样单对账

用手机客户页、Pad 团员页和桌面财务页走完 R1。三次验收后，60 元分别记为派抽 6 元、执行报酬 51 元和团费 3 元。R2 由团员代录，客户在确认一日后取消。手机派单页登记 15 元和 25 元两笔实退，结单后个人及团费按 2、17、1 元入账。测试代理丢弃首笔退款的成功响应后，重新打开表单仍可查看原金额、时间及凭据，并用原请求号核对。财务可从流水回到对应服务订单。[代跑 HTTP 验收](../../server/test/club-service-orders.e2e.mjs)

### 陪玩与共用账簿

客户浏览器使用纽约时区填写北京时间 20:00–22:00 的四段预约，服务端保存的实际预约从 UTC 12:00 开始，四份完成凭据与客户确认均可在管理端核对。手机派单页办理 C2 的 10 元、20 元两笔退款。Pad 团员页办理 C1 结单，桌面财务从团费流水进入正确的陪玩明细。C1 净收 60 元，派单人、执行人、团费分别记 6、50、4 元。C2 净收 30 元，分别记 3、25、2 元。[陪玩 HTTP 验收](../../server/test/club-companionship.e2e.mjs)

混合账簿的浏览器走查使用同一数据库、执行人及派单人，依次结单送心 25 元、代跑 60 元、两笔陪玩 60 元及 30 元。四笔净收共 175.00 元，执行人 146.00 元、派单人 17.50 元、团费 11.50 元。分别从团员个人余额点击三种收入分录，均打开对应原单。三阶段合并后，全仓构建通过，HTTP 集成 80 项、PWA 10 项、单元及领取记录测试共 10 项通过。
