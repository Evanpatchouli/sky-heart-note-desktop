# 管理端原型

[打开运营仪表盘](index.html#/dashboard) ｜ [订单监管](index.html#/club/orders) ｜ [团员管理](index.html#/club/members) ｜ [抽成规则](index.html#/club/rules) ｜ [财务对账](index.html#/club/finance)

本原型直接使用 `admin` 工作区安装的 React、Ant Design 6 与 Ant Design Icons。打开即以虚构管理员身份评审，头像菜单可进入团员与客户端原型。样单操作保存在浏览器本地。正式管理端登录和发布构建继续使用原有入口。

现有原型与截图保留旧计量样单，用于走查布局、权限入口和操作顺序。正式管理端按赠送次数核对日量、总量、待承接和履约，实际到账以颗数单列。单价、派抽、团抽均按元/次展示。有授权的管理员调整每次团抽金额，配置更新只用于全新订单，原单续段沿用首段的每次派抽与团抽。跨期改价按剩余已付次数与双方约定的每次单价核对。正式财务页可核对本单派单人确认结单及入账流水。相关字段、统计及配置界面待适配。[送心业务细则](../../heart-delivery.md) · [正式验收任务](../../todo.md)

## 现有页面与新增页面如何保持一致

| 参照 | 原型的做法 |
| --- | --- |
| 整体布局 | 与正式后台共用 `AdminShell` 和菜单组件。宽屏沿用 200px 深色侧栏、64px 白色页头、右侧蓝色头像、灰色页面背景及页脚 |
| 主内容 | 沿用桌面 24px 内容内边距、8px 内容区圆角，使用默认主题 token。新增业务通过侧栏的「俱乐部管理」进入 |
| 系统页面 | 系统用户、系统角色和权限示例直接引用现有页面源码。原型构建将用户与角色接口映射为本地样例 |
| 默认首页 | 运营仪表盘以订单和本地结算账簿为数据源，使用与既有后台相同的 Ant Design 统计卡、表格、进度条和标签 |
| 俱乐部列表与操作 | 使用实际的 Ant Design `Table`、`Tag`、`Select`、`Form` 和 `Button`。编辑用 `Modal`，长明细用 `Drawer`，对账入账保留二次确认 |
| 手机和 Pad | 沿用 `lg` 断点折叠侧栏。窄屏展开导航覆盖内容，选页即收起。订单表在窄屏保留摘要和详情入口，团员和规则页可展开行查看额外属性，手机明细抽屉占满可用宽度 |

## 从原型仪表盘进入日常工作

原型首页按旧口径汇总本地样单。四项指标均可点击，进入订单监管后会保留对应筛选。正式仪表盘以次数核对待承接和交付，并独立汇总实际到账颗数，具体见 P1-30。

| 指标或待办 | 计算口径与操作 |
| --- | --- |
| 待派单订单 | 已提交、尚未正式派发的订单数。点击查看派单人及订单 |
| 待承接份额 | 可继续承接的已派发订单中，订购量减去已分配份额，包含公开及定向余量。点击可核对相应订单 |
| 累计实际到账 | 按各订单的实绩累计老板实际收到的爱心，保留停送前的交付。点击进入已有到账记录的订单 |
| 改价与退款待办 | 待提交改价、待老板答复、待登记补款和停送待退款的订单合计。点待办行直接打开该订单详情 |
| 来源与结算 | 按直接派单、客户端下单分别看单数及到账颗数。财务区使用独立结算样单，点击金额可核对指定结算单。确认入账后返回首页，待入账笔数及金额下降，已入账团费净额同步更新 |

## 旧原型业务页走查

1. **订单监管**。按来源、状态、单号或姓名筛选，点「详情」核对派单人、分配份额、实际到账、规则版本和收退款记录。旧按颗样单 `HX-1124-07` 的原单实收 70.00 元，10 颗跨期产生 1.50 元拟补差。团员端登记实补或实退后，再回这里核对原型的净实收。
2. **团员管理**。编辑团员的“派单”标记。在同一浏览器、同一预览地址的客户端重新下单，未指定派单人时使用更新后的随机候选名单。未标记团员仍能直接派单和接单。本地演示在候选为空时显示提示。正式验收覆盖无合格候选时建待分配订单、团长或副团长手动分配、老板分配前取消。[P1-24 验收](../../todo.md#p1--报价派接单与每日履约)
3. **抽成规则**。原型「编辑规则」仍显示到账颗数或赠送次数的旧开关及双倍期试算。可更改演示配置，再用团员端发布新单，核对新发布订单与历史规则快照的展示。正式抽成配置统一为每次金额。
4. **财务对账**。核对两笔独立的结算样单。普通单实收 50.00 元，派单人和团费各 5.00 元，两名送心员各 20.00 元。买 100 送 5 样单实收 50.00 元，派抽 5.25 元，送心员收入 42.00 元，团费收入 5.25 元、活动支出 2.50 元。原型用财务页的确认入账按钮演示流水，重复打开同单仅显示原有演示结果。「重置财务样例」可重新走查。

订单监管、派单标记和规则设置与团员端、客户端共用演示业务数据。财务对账有独立的可重置账簿，系统管理页也使用独立的样例账号。进入原型无需输入真实账号和密码。真实通知、数据库入账与权限校验按[业务任务清单](../../todo.md)另行验收。

## 启动与复现

初次使用在仓库根目录安装锁定依赖并构建共用包。随后执行以下命令，Vite 会输出相对路径的静态资源到本目录的 `dist/`。原型程序和构建配置纳入版本管理，`dist/` 由构建生成。

```sh
pnpm install --frozen-lockfile
pnpm --dir common build
pnpm --dir admin build:prototype
python -m http.server 5190 --bind 127.0.0.1 --directory docs/design
```

打开 `http://localhost:5190/admin/`。要与另外两端联动，请也通过 `http://localhost:5190/prototype/` 打开它们，使用相同主机名和端口。仅开发管理原型时可运行 `pnpm --dir admin dev:prototype`，默认端口为 5191，其浏览器存储独立。正式后台仍通过 `pnpm dev:admin` 或已有 Docker 服务运行。
