# 俱乐部三端设计评审稿

范围为 P1 送心。管理端沿用已有 Ant Design 后台，团员端采用飞书工作台式的任务队列，客户端采用微信服务页式的订单和收支摘要。三端可围绕同一笔样单走查，正式应用的开发进度由[任务清单](../todo.md)追踪。

正式设计按赠送次数展示日量、总量、份额和履约进度，单价、派抽、团抽均为元/次。建单时保留预计实收颗数，接单时保留实际实收颗数，日报另记实际到账。现有可点击原型和截图保留旧计量样单，用于走查页面布局和操作顺序。计量字段、截量领取、改派及日报流程待适配。[业务规则与验收算例](../heart-delivery.md) · [正式交互规范](style-guide.md)

[管理端 · 运营仪表盘](admin/index.html#/dashboard) ｜ [团员端 · 接单区](prototype/index.html#member/board) ｜ [团员端 · 我的承接](prototype/index.html#member/mine?view=timeline) ｜ [客户端 · 我的订单](prototype/index.html#client/orders) ｜ [视觉与交互规范](style-guide.md)

将仓库下载到本地，直接用浏览器打开 `prototype/index.html` 即可。也可在仓库根目录运行以下命令，通过 `http://localhost:5190/prototype/index.html` 访问。图标、脚本和样单都在本地。使用同一浏览器、同一个地址打开两个视角可以联动。禁用本地存储时，可在同一个页面内切换视角继续操作。

管理端使用真正的 Ant Design 构建产物，首次需要执行 `pnpm --dir admin build:prototype`。三个原型在同一个 HTTP 服务中可联动。[管理端构建步骤、原后台对照及四个评审流程](admin/README.md)

```sh
python -m http.server 5190 --bind 127.0.0.1 --directory docs/design
```

## 使用旧原型评审交互

**1. 从老板下单走到履约。** 在客户端「下单」填游戏昵称，选普通期和数量，指定青禾或使用随机分配。提交后记下订单号，该单来源是“客户端下单”，状态为“待派单”，登记的现金实收仍为 0。点「演示设置」切到团员端并选中本单派单人，在「派单」中核对示例收款并主动发布。切换另一位团员，打开铃铛中的通知，会定位到同一笔订单。手动抢单并确认数量后，到「我的」选中该承接记录，填写实际赠送次数。切回知夏的客户端核对旧版进度展示。

**2. 验证通知和权限。** 以青禾体验，公开单 `HX-1124-12` 初始可领 50 颗。`HX-1124-11` 定向给青禾，`HX-1124-10` 定向给阿澄，`HX-1124-09` 已领满。比较各单的动作和状态。用「直接派单」发布新单，也会产生一条面向演示成员的通知，来源保持“直接派单”。本原型以站内铃铛演示全员通知和回跳，真实系统推送的实现与实机验收见 P1-25～P1-28。

**3. 走查补退的操作顺序。** 旧客户端样单 `HX-1124-07` 按颗计价，已付 70.00 元，双倍期送 95 次、到账 190 颗。派单人已为余下 10 颗提交改价原因。以下是原型仍显示的旧结果，两次之间用「演示设置 → 恢复初始样单」重置。

| 老板在订单详情中的选择 | 切到团员青禾，在「派单」登记 | 客户端应看到 |
| --- | --- | --- |
| 同意补差 | 同意后仍显示原实付 70.00 元，待确认补款到账。青禾核对后登记 1.50 元 | 累计实付 71.50 元。云岫可继续送余下的 10 颗 |
| 拒绝补差并停送 | 拒绝后应退 3.50 元、已退 0 元。青禾在演示中登记实际退款 | 已退 3.50 元、净付 66.50 元，保留已经到账的 190 颗 |

要审查改价发起表单，可在「演示设置」选择“从提交改价前开始”。青禾填写原因并提交后，知夏的订单才会出现确认操作。

正式验收用 100 次、原付 50.00 元的样单。已送 95 次，剩余 5 次拟由 0.50 改为 0.60 元/次。同意且登记 0.50 元实补后续送。拒绝则停送，应退 2.50 元，实际退足后净付 47.50 元。仅到账倍率变化时差额为零。[按次计价的新算例](../heart-delivery.md#已付款订单如何变更)

## 评审边界

- 样单使用虚构成员、固定业务日和本地金额记录。切换身份、重置场景属于评审工具。审核正式页面时，重点看导航、信息顺序、确认前后金额和可执行动作。
- 旧原型仍含普通期 0.50 元/颗、双倍期 0.35 元/颗和计抽口径切换。正式应用按元/次报价和计抽。买赠活动的团费支出与普通单分账可在管理端的财务样单中核对。[正式业务算例](../heart-delivery.md)
- 原型通过另一名团员领取样单走查发布与领取。正式业务允许同单自派自接，并由本单派单人直接改派未送次数。按日能力截量、多人争抢最后可领次数的原子校验及日报提交后的进度更新见正式验收。[任务清单](../todo.md)
- 团费、个人余额的正式入账、PWA 安装更新与系统推送按开发任务单独验收。旧个人库已有导入工具，归属到未来俱乐部订单的迁移按 P1-03 验证。代跑、陪玩的专属表单待各自实际样单确认后扩展。正式登录的验证码弹窗及跨端借用沿用现有流程。
- 反馈时请注明端、设备宽度、订单号、当前身份以及点了哪个动作。涉及改价、退款或接单权限的意见，同时对照[订单和通知规则](../club-business.md)记录。
