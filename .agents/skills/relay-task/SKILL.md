# 跨会话任务接力

调用示例：`$relay-task 在当前项目发起接力，完成 roadmap 的 P1，以其中的验收条件为准。允许每任自行创建同项目后继。`

## 发起与绑定

- 用户要求发起接力时，默认由当前会话担任首任；明确要求另开首任时，将目标和授权直接写入新会话的首条消息。若用户只要提示词，就交付可直接发送的文本，由用户发起。
- 提取目标、约束、验收条件和用户授予的逐代接力权限。各任遵循项目自身的 Agent 指令、验证、提交和文档约定。
- 按运行环境绑定目标项目。若宿主有项目登记，记录并核对项目标识、主机和工作区根路径；若宿主按目录启动独立会话，以同一主机上的规范化绝对路径绑定工作区。每一任（包括首任）写入前都核对当前会话归属和实际工作目录。遇到重名、归属冲突或无法确认时，报告具体问题，避免回退到默认项目。
- 根据宿主实际提供的能力查询窗口用量、创建新会话及确认受理。**在 Codex 桌面端使用时，先读 [Codex 适配说明](references/codex.md)**。其他宿主使用自身支持的接口；缺少可靠用量或建会话能力时，按下文的回退方式处理。
- 按项目约定选择任务和交接记录的位置；没有约定时，可为本次任务单独保存一份记录。写入固定目标、约束、验收、接力授权、项目绑定、阈值和本技能入口，保留已有的其他任务与用户改动。

## 执行与交接时机

每任开始时、每个可验证工作单元结束时，以及读取大量材料前，检查当前会话的上下文用量，并在单元结束时记录进度。使用宿主提供的当前窗口用量；默认主动交接线为 **80%**，用户可覆盖。达到阈值时收尾。如果下个单元可能挤占交接空间，也可以提前交接。无法采样时，在可验证的工作边界提前收尾，记录原因。若已经发生压缩，从磁盘核对现场后再续做。

目标已验收时，由当前会话直接交付。若剩余工作全部依赖用户或外部条件，记录真实阻塞并报告。仅在仍有工作可推进且需要换会话时创建后继。

## 交给下一任

1. 收回仍会写入的子任务。记录当前分支与提交（如适用）、未提交现场、已完成的验收项及证据、失败与未验证项、剩余工作和**接手后的第一个具体动作**。附上交接原因和最近一次可靠采样。派发前结束本任对共享工作区的写入。
2. 重新核对绑定，通过宿主显式指定同一项目和同一工作区，创建恰好一个全新会话。新会话只接收首条消息和项目内的接力记录，无需继承或追读历任聊天。若宿主无法定向创建或绑定失效，交付可手动发送的接棒消息。
3. 后继的首条消息须填写实际值，并逐代传下绑定与授权。可用以下格式：

   > 你是本次任务接力的当前主会话。目标为〈目标〉，约束为〈约束〉，验收以〈依据〉为准。请核对〈项目绑定及工作区〉，按〈技能入口〉和项目指令继续。已验证〈结果〉，尚待〈事项〉。先读〈接力记录路径〉，从〈第一步〉开始。用户已授权每任在当前窗口占用达到〈阈值〉或下一单元会挤占交接空间时，更新记录，并在这个项目和工作区创建唯一的直接后继。请将相同的绑定、授权、阈值和停止条件传给下一任。交接受理即结束本任；验收完成或出现真正阻塞时结束接力。

4. 创建受理后报告后继标识并立即结束，不等待后继回复或持续监测。若创建结果不明确，用宿主可用的查询能力一次性核对本次派发；仍无法确认时保留记录并报告，避免重复创建。
